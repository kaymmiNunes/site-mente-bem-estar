**Turma:** 3º A  
**Grupo:** 2  
**Projeto:** **AcolheMente**  

---

## Apresentação do projeto ao grupo

Grupo, a proposta de vocês é criar um **site sobre saúde mental e bem-estar** com a função de informar, acolher e orientar usuários da escola. O projeto também pode reunir conteúdos relacionados à saúde, psicologia, educação física e hábitos saudáveis, sempre com linguagem simples e acessível.

O mais importante é entender que esse projeto **não substitui atendimento profissional**. O site deve funcionar como um espaço de orientação inicial, acolhimento, incentivo ao cuidado com a saúde e divulgação de informações úteis para a comunidade escolar.

Vocês não precisam criar um sistema complicado. O melhor caminho é produzir um site **simples, claro, respeitoso e funcional**, que consiga apresentar informações importantes, orientar o usuário e mostrar caminhos de apoio dentro da escola.

Durante o desenvolvimento, o grupo precisa manter organização, dividir tarefas, registrar decisões, revisar o conteúdo com cuidado e salvar as versões do projeto no GitHub. Isso ajuda a evitar confusão, perda de arquivos e atrasos.

## 1. Análise simples da proposta do projeto

O projeto de vocês pretende criar um **site educativo e acolhedor** voltado para saúde mental e bem-estar no ambiente escolar. A ideia é oferecer orientações simples, conteúdos informativos e apoio inicial para estudantes que precisem de incentivo, escuta ou direcionamento.

### O que esse projeto pretende resolver
Muitas pessoas enfrentam estresse, ansiedade, cansaço, desmotivação ou dificuldades emocionais, mas nem sempre sabem onde buscar informações claras e acessíveis. Em alguns casos, também faltam espaços escolares organizados para orientar os alunos sobre autocuidado, bem-estar e apoio.

### Problema principal
O problema principal é a **falta de um espaço simples e acessível para informar, acolher e orientar estudantes sobre saúde mental e bem-estar**.

### Objetivo geral da aplicação
O objetivo do site é **acolher usuários da escola, divulgar informações importantes sobre bem-estar e orientar de forma simples sobre práticas de cuidado físico e emocional**.

### Utilidade do sistema no dia a dia
Esse site pode ajudar a:
- orientar estudantes sobre hábitos de bem-estar;
- reunir dicas de autocuidado;
- apresentar conteúdos sobre saúde mental de forma acessível;
- incentivar práticas saudáveis, como atividade física, organização da rotina e descanso;
- mostrar canais de apoio da escola ou da comunidade;
- acolher o usuário com linguagem respeitosa e clara.

### Público-alvo
O público-alvo pode ser:
- estudantes da escola;
- jovens que precisam de orientação sobre bem-estar;
- comunidade escolar em geral;
- usuários que procuram informações simples sobre autocuidado e saúde emocional.

### Possíveis funções principais do sistema
O site pode incluir:
- página inicial de apresentação;
- seção sobre saúde mental;
- seção sobre bem-estar e autocuidado;
- seção com hábitos saudáveis;
- orientações sobre sono, rotina, exercícios e alimentação;
- página com contatos ou canais de apoio;
- formulário de contato ou pedido de sugestão;
- mensagens acolhedoras ou dicas do dia;
- quiz simples sobre bem-estar;
- área com orientações do tipo “quando procurar ajuda”.

## 3. Levantamento de requisitos

### O que são requisitos
Requisitos são as necessidades do projeto. Eles mostram o que o sistema precisa fazer e como ele deve se comportar.

### Diferença entre requisitos funcionais e não funcionais
**Requisitos funcionais** são as funções do sistema.  
Exemplo: abrir páginas, mostrar textos, exibir contatos, responder a botões.

**Requisitos não funcionais** são características de qualidade.  
Exemplo: ter linguagem clara, ser acessível, ter boa organização visual e funcionar bem no navegador.

### Quais requisitos esse projeto provavelmente terá
Como o projeto é um site educativo e acolhedor, ele precisa apresentar informações com clareza, ter linguagem respeitosa, ser fácil de navegar e funcionar bem no ambiente escolar.

### Requisitos funcionais
- O sistema deve exibir uma página inicial.
- O sistema deve apresentar informações sobre saúde mental e bem-estar.
- O sistema deve possuir menu de navegação.
- O sistema deve mostrar conteúdos sobre autocuidado, rotina, atividade física, descanso e apoio.
- O sistema pode exibir dicas ou mensagens acolhedoras.
- O sistema pode mostrar contatos ou canais de apoio da escola.
- O sistema pode ter um formulário de contato ou sugestões.
- O sistema pode apresentar um quiz simples sobre bem-estar.
- O sistema deve permitir leitura fácil do conteúdo.

### Requisitos não funcionais
- O site deve ter linguagem simples e respeitosa.
- O site deve ter aparência organizada e agradável.
- O site deve funcionar em navegador comum.
- O conteúdo deve ser educativo e acolhedor.
- O sistema deve evitar excesso de texto técnico.
- Os arquivos devem estar bem organizados.
- O projeto deve ser simples de manter e atualizar.
- O site deve ser possível de concluir até agosto.

## 4. Tecnologias indicadas

Para esse projeto, a melhor escolha é usar tecnologias simples e adequadas para iniciantes.

### HTML
HTML serve para criar a estrutura do site: títulos, textos, imagens, links, menus, botões e divisões da página.

### CSS
CSS serve para cuidar da aparência: cores, tamanhos, espaçamento, alinhamento e organização visual.

### JavaScript
JavaScript serve para colocar interações no site, como:
- mostrar mensagens de apoio;
- responder a botões;
- exibir dicas do dia;
- criar um quiz simples.

### GitHub
GitHub serve para guardar o projeto, registrar a evolução do grupo e evitar perda de arquivos.

### Tecnologias recomendadas para este projeto
- HTML
- CSS
- JavaScript
- Git e GitHub
- Editor de código, como VS Code

### Alternativa simples para ambiente escolar
A melhor escolha para o grupo é criar um **site estático**, sem banco de dados e sem servidor. Isso já é suficiente para um projeto escolar bem apresentado.

Se o grupo quiser adicionar algo a mais, pode usar JavaScript com `localStorage` para guardar preferências simples, mas isso é opcional.

### Por que essas tecnologias são boas para esse projeto
Porque são:
- mais fáceis para iniciantes;
- simples de testar;
- adequadas ao tempo disponível;
- suficientes para um site educativo e acolhedor.

## 7. Primeira versão do projeto

A primeira versão funcional não precisa estar perfeita. Ela precisa mostrar que o projeto já começou de verdade e que o grupo conseguiu transformar a ideia em algo concreto.

### O que deve existir na primeira versão funcional
- página inicial pronta;
- menu funcionando;
- pelo menos 3 seções ou páginas com conteúdo;
- visual básico organizado;
- pelo menos uma interação simples com JavaScript.

### O que pode estar simples ou incompleto
- quantidade de texto ainda pequena;
- visual ainda simples;
- poucas imagens;
- quiz curto;
- formulário sem envio real.

### O que é mais importante nessa primeira entrega
O mais importante é que:
- o site abra corretamente;
- os links funcionem;
- o conteúdo principal esteja presente;
- a proposta do projeto esteja clara e respeitosa.

### Como saber se essa versão já pode ser apresentada
A primeira versão já pode ser mostrada quando:
- o site funciona sem erro grave;
- as páginas podem ser abertas;
- há conteúdo suficiente para entender a proposta;
- o grupo consegue explicar o que já foi desenvolvido.

## 8. Orientação de commit no GitHub

### O que é commit
Commit é um registro de uma mudança feita no projeto. É como salvar uma etapa do trabalho com um nome explicando o que foi feito.

### Por que usar GitHub
O GitHub ajuda a:
- guardar o projeto online;
- evitar perda de arquivos;
- mostrar a evolução do grupo;
- organizar o trabalho.

### Como criar um repositório
1. Entrar no GitHub.
2. Clicar em **New repository**.
3. Escolher um nome, por exemplo: `acolhemente`.
4. Criar o repositório.
5. Copiar o link do repositório.

### Como organizar os arquivos antes de enviar
Antes de enviar:
- conferir os nomes dos arquivos;
- deixar tudo nas pastas certas;
- remover arquivos repetidos;
- garantir que o site abre normalmente.

### Exemplo de comandos básicos

```bash
git init
git add .
git commit -m "Estrutura inicial do projeto"
git branch -M main
git remote add origin LINK_DO_REPOSITORIO
git push -u origin main
```

### Comandos para novas atualizações

```bash
git add .
git commit -m "Adiciona páginas de bem-estar e apoio"
git push
```

### Exemplos de mensagens de commit
- `Estrutura inicial do projeto`
- `Cria página inicial`
- `Adiciona menu de navegação`
- `Adiciona estilo CSS do site`
- `Implementa botão de mensagem de apoio`
- `Organiza páginas internas`
- `Corrige layout e textos`
- `Prepara primeira versão funcional`

### O que deve ser commitado na primeira versão
- `index.html`
- páginas internas criadas;
- `style.css`
- `script.js`
- imagens utilizadas;
- `README.md`
